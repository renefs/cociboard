# Review 0017 — v0.23.0 household preferences (planning/review model: Opus)

Scope: the v0.23.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (586 pytest, 574 vitest, ruff, mypy --strict, tsc,
ESLint, version check).

## Code review
- Settings storage:
  - single-row `household_settings` table (`CHECK id = 1`), created by a clean,
    SQLite-compatible migration 0007;
  - `GET` returns the defaults until the first `PUT` writes the row;
  - validation is pure (`household.py`): dietary subset, `HH:MM` times, no property both
    required and avoided, with the `invalid_time`, `not_dietary` and
    `required_and_avoided` codes.
- Rules:
  - `variety.py` takes a frozen `VarietyTargets` (defaults = the old constants); a minimum
    of 0 turns its check off, and the issue params follow the targets;
  - `suggest.py` filters with `allowed_by_preferences`, using tags as they are (no vegan →
    vegetarian inference);
  - manual assignment (`PUT` slot) is never checked.
- Backups:
  - format v5 carries the settings;
  - restoring v1–v4 resets them to the defaults;
  - `expunge_all()` after the restore deletes avoids a stale cached row.
- Frontend:
  - the dialog uses fieldsets with legends, so the two "Vegetarian" boxes are told apart;
  - a property ticked in Diet is disabled in Avoid;
  - the save is optimistic and serialized in the `household` scope, pauses offline, and
    invalidates the weeks and candidates;
  - the `.ics` export uses the configured times, and DTEND wraps past midnight.

## Findings
- Fixed: the slot picker hid every recipe outside the preferences, so "you can still add
  them by hand" held only in the recipe panel, and the picker is the main way to fill a slot
  on phones. `candidates_for_slot` now lists them last with a new `outside_preferences`
  reason, never as a good pick. Updated tests, README (including the API table), ADR-0026
  and CHANGELOG.
- Fixed: the slot picker's list had the same whole-list `aria-live` as the recipe list.
  Only the result count is announced now (test added).

## Accepted as-is
- The steppers' "−" stays enabled at the minimum. The value is clamped, so it only looks
  clickable.
- `PUT` replaces the whole object: a partial body resets the missing fields to their
  defaults. The UI always sends the full object.
- A household that requires tags its recipes don't carry gets empty Suggest results. The
  toast says that preferences left slots empty.
