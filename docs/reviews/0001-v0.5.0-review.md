# Review 0001 — v0.5.0 (planning/review model: Opus)

Scope: the whole codebase at `v0.5.0`, plus manual checks in the browser at 1440px and
375px. Each milestone v0.1.0–v0.5.0 was also reviewed when it was committed. Fixes from
those reviews went into the next milestone: compact recipe cards in v0.3.0, and readable
recipe names in the 7-column grid in v0.4.0.

## Verified manually
- Mouse drag from the recipe panel to a slot, moves between slots, and drops refused on
  incompatible slots (a dinner-only recipe on lunch).
- Plans persist across reloads; week navigation; Suggest fills the empty slots with a
  varied week and offers Undo.
- Mobile 375px: stacked day cards, a bottom-sheet picker that lists only compatible
  recipes.
- Recipe form layout and validation hints.

## Findings

### 1. Plan mutations race on the network (medium)
`usePlanActions` applies optimistic changes in order, but the requests are sent
concurrently. Take two quick actions that touch the same slot, such as move A→B then
B→C, or two drops on one empty slot. The server can receive them out of order and
answer with a spurious 404 ("source slot is empty") or a 500 from the unique
constraint. The UI then rolls back and refetches, which shows up as a flicker or an
error toast for something the user did correctly.

**Decision:** serialise the plan requests per week on the client, in a FIFO queue, and
keep the optimistic update immediate.

### 2. Unique-constraint violations surface as 500 (medium)
In `planner.assign_slot`, `suggest_week` and `replace_week`, a concurrent write (for
example a second tab) can raise `IntegrityError` on `uq_week_day_slot`. FastAPI turns
that into a 500.

**Decision:** roll back the session and answer `409 Conflict` with "The plan changed
meanwhile; reload and try again". The frontend maps 409 on plan endpoints to that
message and refetches.

### 3. Identity comparison of enums (low)
`repository.update_recipe` compares `data.meal_type is not recipe.meal_type`. This works
today because both values are enum members, but `!=` states the intent and keeps
working if the column ever returns plain strings.

## Accepted as-is
- `_load_recipes` runs one query per assignment, at most 14 per week. This is fine at
  this scale; revisit if weeks are ever aggregated.
- No migration tool yet (`create_all`), already recorded in ADR-0003.
- The httpx deprecation warning from starlette's `TestClient` is harmless.
