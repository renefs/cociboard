# Review 0019 — v0.25.0 end-to-end tests (planning/review model: Opus)

Scope: the v0.25.0 working tree written by the development subagent (Sonnet), before the
commit. Gates:
- `make check` passes: 611 pytest, 616 vitest, ruff, mypy --strict, tsc including the E2E
  tsconfig, ESLint, version check.
- `make e2e` passes: 55 tests, desktop and phone, about 1 minute with the build.
- `CI=1 npx playwright test --repeat-each=2` passes: 110 tests.

## Code review
- Setup:
  - the built frontend is served by the real backend (`COCIBOARD_STATIC_DIR`);
  - one throwaway SQLite database per server, on ports 8766 and 8767 (overridable), wiped
    at start and removed in the global teardown;
  - seeding, auto-backups and recipe import are off;
  - the config never builds; `make e2e` builds first.
- Isolation:
  - `workers: 1`;
  - an `auto` fixture restores a fixed v6 backup through the API before every test;
  - the page fixture waits for in-flight `/api` requests before the next reset, so a late
    optimistic save cannot leak into the next test;
  - the service worker is blocked except in the offline spec.
- Locators are by role and label. The only CSS locator is the drag overlay, which has no
  role.
- CI:
  - a new `e2e` job caches the browser by the Playwright version and installs the system
    libraries every run;
  - the report and traces are uploaded when it fails;
  - docker-publish calls the whole `ci.yml`, so E2E gates the image.
- App fixes from axe: Label in Name for the variety badge and filled slots, with new i18n
  keys in both languages and unit tests updated.

## Verified manually
- Ran the gates above locally.
- The new CI job has not run yet; it runs on push.

## Findings
- Fixed: "move a meal to another slot, then clear a slot" failed about 1 run in 5 locally:
  - request logging showed the Remove click sent no request when it came within about 20 ms
    of the drop;
  - cause: dnd-kit's drop animation leaves the drag chip over the grid for a moment, and it
    takes the click;
  - `dragWithMouse` now waits for the chip to be gone; 30 repeats of the spec passed after
    the fix.
- Fixed: the drop animation ignored `prefers-reduced-motion`. `DragOverlay` now gets
  `dropAnimation={null}` when reduced motion is requested (CHANGELOG).

## Accepted as-is / follow-ups
- Possible app bug reported by the subagent: when a keyboard drag starts from a filled slot,
  dnd-kit's first announcement can name a neighbouring slot. Pressing Space at once then
  moves the meal there instead of leaving it. Arrow keys behave. The keyboard spec works
  around it, and it deserves its own fix.
- The reduced-motion `dropAnimation` change has no unit test: jsdom does not run dnd-kit
  drags.
- The axe scans run with `reducedMotion: "reduce"` to avoid contrast false positives on
  fading elements; no rule is disabled.
