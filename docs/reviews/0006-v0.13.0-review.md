# Review 0006 — v0.13.0 special meals and slot notes (planning/review model: Opus)

Scope: the v0.13.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes. Migration `0004_slot_special_and_note` rebuilds
`mealassignment`.

## Verified manually
- 1440px:
  - Friday dinner's picker shows the three chips (Comemos fuera, Sobras, Libre) above the
    search. Choosing "Comemos fuera" fills the slot and announces it.
  - **Add note** on that slot opens a small form (max 120, hint), and the note
    "Cumpleaños de Ana" shows under the special.
  - **Suggest** then fills the other 13 slots and leaves Friday dinner as it was. The
    shopping list has no ingredients for it.
  - A recipe slot with the note "Hacer doble ración" keeps the note after **Replace**
    picks another recipe (the UI re-sends the note). The note is part of the slot's
    accessible name.
- 375px: specials have a dashed, calm style and no horizontal scroll (see finding 1 for
  notes).
- Docker image built with podman from the working tree, started on a real v0.12.0
  database (revision 0003, 28 planned meals). It writes `bak-0003_recipe_archived_at-*`
  and migrates to 0004. All 28 rows are kept with the FK to `recipe`, both indexes and the
  unique autoindex, and a "leftovers" special with a note can be saved.

## Findings (fixed in this release)

### 1. Notes were cut to one line on phones (low)
At 375px a slot is ~140px wide, so "Cumpleaños de Ana" showed as "Cumpleaño…". **Fix:**
`.slot-note` clamps to two lines and wraps long words.

### 2. Keyboard instructions only mentioned recipes (low)
"To pick up a recipe…" also applies to special meals now. **Fix:** the text now says "a
recipe or a meal" in both languages.

## Accepted as-is
- Replace keeps a note because the client re-sends it. A note dropped by a client that
  doesn't re-send it is acceptable, and it is documented in ADR-0016.
- Migration 0004, like 0003, does nothing if the columns already exist.
- SQLite doesn't enforce foreign keys in this app (no `PRAGMA foreign_keys`). That was
  already true; the rebuilt table keeps the declared FK.
