# Review 0007 — v0.14.0 mobile navigation and Today view (planning/review model: Opus)

Scope: the v0.14.0 working tree written by the development subagent (Sonnet), before the
commit. Frontend only; gates: `make check` passes.

## Verified manually
- 375px:
  - The app opens on **Hoy**: today's lunch (recipe, prep time, ingredient chips) and
    dinner (a "Sobras" special with its note), then tomorrow.
  - The bottom bar (Hoy · Semana · Recetas · Compra) marks the active tab. Focus moves to
    the view's heading, `?view=` follows the tab, and a reload keeps it.
  - **Añadir** on a recipe in Recetas switches to Semana with the select banner. After
    the fixes below, the empty Saturday lunch is centred above the bar. Tapping it places
    the recipe, and the toast sits above the bar.
  - **Compra** shows the shopping list inline (no dialog).
- 1440px: the layout is unchanged (panel and grid side by side, no tab bar, `?view=`
  ignored) and there is no horizontal scroll.

## Findings (fixed in this release)

### 1. Select mode scrolled to a filled slot instead of the empty one (medium)
With a nearly full week, **Add** scrolled to the first compatible slot (Monday lunch,
already filled, which would be replaced) instead of the only empty one (Saturday lunch).
On a phone this is the main way to plan. **Fix:** an empty compatible slot is marked
`data-select-target="empty"` and is preferred. Covered by `WeekGrid` tests.

### 2. The scrolled-to slot was half hidden behind the tab bar (medium)
`scrollIntoView({ block: "nearest" })` aligned the slot with the bottom of the viewport,
under the fixed bar. **Fix:** the target is centred (instant under reduced motion), and
below 900px `html` gets `scroll-padding-bottom` for the bar, which also helps keyboard
focus.

## Accepted as-is
- A recipe card can still be dragged on the Recetas tab, with nowhere to drop it. **Add**
  is the intended path there.
- The tab-bar colours reuse existing tokens. `contrast.test.ts` doesn't list the new
  pairs, but the colours are pairs already checked elsewhere.
- iOS safe-area padding (`env(safe-area-inset-bottom)`) was not checked on a real device.
