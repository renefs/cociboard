# Review 0013 — v0.19.0 automatic backups and enforced foreign keys (planning/review model: Opus)

Scope: the v0.19.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (371 pytest, 415 vitest, ruff, mypy --strict, tsc,
ESLint, version check).

## Code review
- Every SQLite connection gets `PRAGMA foreign_keys=ON` through one connect listener, in
  the app engine and the test fixture. Migrations run on a connection where the pragma is
  switched off before any transaction, then restored in a `finally`; violations found
  after migrating are only logged, and the startup integrity step deals with them.
- The integrity step runs `quick_check` (logged, never blocking) and `foreign_key_check`.
  Orphaned planned meals are deleted only after an `integrity` copy succeeds; any other
  violation is logged and left alone. The step never raises.
- Copies rotate by kind: migration (incl. `legacy` and `integrity`) 3, pre-restore 3,
  automatic `COCIBOARD_BACKUPS_KEPT` (7). Existing file names keep rotating as before.
- `backup_due` is pure: no copy yet → copy; otherwise only after the interval **and** if
  the database (or its WAL) changed, so quiet weeks don't replace the history with
  identical copies. The loop checks every 15 minutes, copies off the event loop, and keeps
  the last failure as a code for the UI.
- `GET /api/backup/status` exposes no paths (`custom_dir` is a boolean).

  and an empty `COCIBOARD_BACKUPS_KEPT=`:

  - "quick_check ok", `bak-integrity-…` copy, "Removed 1 planned meal(s) … (weeks:

- Backup dialog, 1440px and 375px: "Copias automáticas — Última copia automática: 20 nov
  2026, 09:07. Se conservan las últimas 7." plus the one-line restore hint.

## Findings (fixed in this release)
### 1. Backup dialog without padding and without scrolling on phones (medium, since v0.11.0)
The dialog uses the full-screen sheet, whose body has no padding and `overflow: hidden`
because the recipe form brings its own. The backup content touched the screen edges and,
now that it is longer, its end was cut off on short phones. **Fix:** `.backup` has its own
padding and scrolls (`flex: 1; min-height: 0; overflow-y: auto`). Checked at 375×560:
16px padding, the content scrolls to the end, no horizontal scroll.

## Accepted as-is
- The time of the last automatic copy is the newest copy's file time; nothing extra is
  stored. A failed copy is retried at the next 15-minute check, and each failure is
  logged.
- Changing `COCIBOARD_BACKUP_DIR` leaves the old copies where they were, unrotated
  (README, ADR-0022).
- Automatic copies live on the same disk as the database unless `COCIBOARD_BACKUP_DIR`
  points elsewhere; downloading a backup file is still the off-device copy.
- Restoring a `.bak-*` file is a manual step (stop, replace the file, start), documented
  in the README; there is no UI for it.
