# Review 0015 — v0.21.0 import a recipe from a link (planning/review model: Opus)

Scope: the v0.21.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (560 pytest, 493 vitest, ruff, mypy --strict, tsc,
ESLint, version check).

## Security review (SSRF)
The server fetches a URL the user types, so this part was read line by line.
- `validate.py` (pure):
  - only http/https, ports 80/443, no userinfo, no backslash, no `%` in the host, IDNA for
    non-ASCII hosts, and legacy numeric spellings (`2130706433`, `0x7f000001`, `127.1`)
    refused up front;
  - every resolved address must be public: `is_global` plus the explicit blocklist
    (loopback, RFC 1918, CGNAT, link-local/metadata, ULA, multicast, documentation, …),
    with IPv4 unwrapped from mapped, 6to4, Teredo and NAT64 addresses;
  - a name with any non-public address is refused, not just the one used.
- `fetch.py`:
  - the host is resolved once and the request goes to the vetted IP, with the original
    name in `Host` and in TLS SNI, so DNS rebinding cannot move it;
  - certificates are verified against the name;
  - `trust_env=False` (no proxies from the environment), no cookies or credentials, and
    redirects are followed by hand: at most 5, each re-parsed and re-resolved;
  - a 2 MiB cap is applied to the decoded stream, so a gzip bomb is cut off;
  - the declared `Content-Length` is checked first;
  - the time limits are 5 s connect, 10 s read and 15 s overall;
  - at most 2 imports run at once, and a third waits 2 s and then gets 429 `busy`;
  - the log has the host and the outcome only, never the path or query.
- `parse.py`:
  - the standard library `html.parser` and `json`;
  - JSON-LD only, with bounded depth and node walk;
  - `RecursionError` from deeply nested JSON is caught;
  - every field is cut to the recipe limits.
- The route saves nothing; it returns a draft for the form. It is behind the auth
  middleware like every `/api` route, and `COCIBOARD_RECIPE_IMPORT=false` turns it off
  (404 `import_disabled`).

## Findings
- Fixed: the route parsed up to 2 MiB of HTML on the event loop, which blocked other
  requests for that time. Parsing now runs in `asyncio.to_thread`, inside the concurrency
  slot, so at most two parses run at once.

## Accepted as-is
- Many sites block automated fetches (403/402), which shows up as "the site didn't answer";
  the form explains that not every site works.
- Only JSON-LD is read (no microdata or HTML scraping); meal type and protein are never
  guessed.
- The charset comes from the `Content-Type` header only; pages that declare it only in a
  `<meta>` tag and aren't UTF-8 may show replaced characters.
- On redirects between two hosts that share an IP, the pooled TLS connection of the
  first host may be reused. The IP was already vetted, so this has no SSRF effect.
- Not verified: the Android share-sheet flow (manifest `share_target`) on a real device, and
  IPv6-only sites.
