- `make e2e` passes: 58 tests; the keyboard, planning and offline specs pass `--repeat-each=5` (60/60).

## Code review
- Persistence:
  - `persistQueryClient` stores only pending mutations of the five optimistic kinds (plan,
    shopping, pantry, household, favourite), in `localStorage`;
  - every access is in try/catch, and writes are throttled and flushed on `pagehide` and
    when the page is hidden;
  - `FORMAT_VERSION` is separate from the app version, so an update keeps waiting edits;
    data older than 7 days or in another format is dropped with a notice;
  - queries are not persisted: the service worker already serves cached GETs.
- `setMutationDefaults` gives restored mutations their functions. Variables are plain JSON
  and carry the week. Each hook passes only its key, scope and `onError`.
- Optimistic state:
  - an overlay at read time (server data + pending changes, through pure `apply…`
    functions) replaces `setQueryData` in `onMutate`;
  - it works the same for in-page and restored changes, and a failed change simply stops
    being overlaid;
  - plan order is kept by `scope: week-<weekStart>` instead of the in-memory `sendInOrder`
    chain; `restore.test.tsx` covers the order after hydrate and resume.
- Failures:
  - a 401 keeps the change pending until sign-in (`retryAfterSignIn` / `notifySignedIn`);
  - a rejected restored change shows a dismissible notice.
- Multiple tabs: a Web Lock elects one tab to restore, send and store.
- Logout and backup restore discard the waiting edits.
- Fixed in passing (pre-existing): reloading the app while offline looped on "Loading…",
  because `AuthGate` unmounted the app whenever the failed auth query was retried. A unit
  test covers it.

## Findings
- Fixed: the subagent had changed "move a meal, then clear a slot" to click Remove in a
  retry loop. Without the loop it failed 34 runs in 40, which pointed to a swallowed click.
  - Cause: dnd-kit swallows every click for 50 ms after a pointer drag ends. It removes its
    document click listener in a `setTimeout(…, 50)`, in `core.esm.js`.
  - With the overlay the slot updates sooner, so the test clicked inside that window.
  - A person cannot click that fast, so this is test timing, not an app bug.
  - `dragWithMouse` now waits 100 ms after the drop, with the reason in a comment, and the
    test uses a plain click again.

## Accepted as-is
- At-least-once delivery: a change in flight when the app closes is sent again on reopen.
  It is harmless for idempotent changes; adding a shopping extra or a pantry staple by name
  can duplicate it. This is documented in the README and ADR-0029.
- A refetch that lands while a move is in flight can briefly re-apply the move, until the
  settle refetch.
- A change made offline in a tab that is not the leader stays in memory only.
- The offline specs run on the desktop project only.
- Not checked by hand in the browser: the E2E offline spec drives the real service worker
  through an offline reload and a close/reopen, which is the behaviour this release adds.
