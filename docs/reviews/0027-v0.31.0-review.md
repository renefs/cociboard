# Review 0027 — v0.31.0 visual refresh, phase 3: recipes and picker (planning/review model: Opus)

Scope: the v0.31.0 working tree written by the development subagent (Sonnet), before the
commit. Phase 3 of the approved mockups: compact recipe rows, the Filters panel, the slot
picker and the Today cards (ADR-0033). Gates:
- `make check` passes (vitest 752 tests in 64 files, pytest 622, ruff, mypy --strict, tsc,
  ESLint, version check).
- `make e2e` passes, with new tests for the Filters panel and the row meta text and axe scans
  of the open Filters panel in light and dark, desktop and phone.
- `make docs-screenshots` passes; `make docs` builds.

## Review
- One row component (`RecipeCard`, the comfortable/compact densities merged) serves the
  panel, the phone Recipes view and the picker; accessible names of the name button, star,
  `+` and drag handle are unchanged, so the planning specs needed no locator changes.
- `activeFilterCount` is a pure function with tests. The Filters button's visible text is
  "Filters 2" with a visually hidden "active", so the accessible name contains the visible
  text (axe `label-content-name-mismatch` failed with an `aria-label`).
- The results line is the single `role=status`, so the count is announced once.
- Accepted deviations: the filter row wraps instead of scrolling (scrolling hid the Filters
  button on a phone); the panel's "Clear filters" resets sort and properties, while the empty
  state's button clears everything.
- Fix made in review: the brief asked for the drag handle to be always visible on touch,
  which undid a deliberate rule (touch users press and hold the row; the handle is for
  keyboard users and took 44px of every phone row). The `(pointer: coarse) and (hover: none)`
  rule hiding it is back.

## Verified manually
At 1440px light: the panel rows, the Filters panel open (sort and property groups), the
