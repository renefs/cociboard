# Review 0003 — v0.10.0 schema migrations (planning/review model: Opus)

Scope: the v0.10.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes.

## Verified manually
- Real legacy databases built from the tagged code: `git archive v0.8.0` seeded 33
  recipes and planned a meal; a copy opened with `git archive v0.9.0` got the shopping
  tables from `create_all` and a manual extra ("Leche").
- `uvicorn cociboard.main:app` (v0.10.0) on each database: both are stamped
  `0001_initial` and upgraded to `0002_shopping_list`, the planned meal and the extra are
  still there, the shopping list answers (9 items), and a
  `cociboard.db.bak-legacy-<timestamp>` copy is written next to each database.
- A backup is a working database: copying the v0.8.0 backup back and starting again
  migrates it the same way.
- Not checked: building the Docker image (no Docker on the review machine). The
  subagent checked that the wheel contains `migrations/` including `script.py.mako`,
  and the image installs that wheel.

## Findings (fixed in this release)

### 1. Migration and backup logs were invisible under uvicorn (medium)
Uvicorn configures only its own loggers, so the `cociboard.migrate` INFO messages
(including the backup path) were dropped. On a NAS the user had no way to learn that a
backup existed or which revision the database reached.

**Fix:** `main.configure_logging()` gives the `cociboard` logger a stream handler at
INFO when it has none, called at startup. Covered by a test. Startup now prints, for
example, `INFO:     cociboard.migrate: Backed up database to ...`.

## Accepted as-is
- SQLite does not roll back every DDL statement, so a migration that fails halfway can
  leave a partly changed database. The backup taken just before is the recovery path,
  and the README explains how to restore it.
- Unknown extra tables in an unversioned database stop the start with `MigrationError`
  instead of migrating. That is safer than guessing; nobody should have such a database.
- Two backups in the same second overwrite each other. That can't happen in normal use.
