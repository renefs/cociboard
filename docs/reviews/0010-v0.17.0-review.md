# Review 0010 — v0.17.0 richer recipes (planning/review model: Opus)

Scope: the v0.17.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (319 pytest, 405 vitest, ruff, mypy --strict, tsc,
ESLint, version check).

## Code review
- Migration 0005 adds `servings`, `steps` (JSON, NOT NULL, server default `'[]'`) and
  `source_url` with batch operations, only when missing (as 0003/0004 do).
- `clean_source_url` is an allow-list: absolute `http`/`https` with a host, no whitespace or
  control characters, at most 500 characters. The client check (`isSafeSourceUrl`) is at
  most as permissive as the server, and the details dialog renders the link only when it
  passes, with `target="_blank" rel="noopener noreferrer"`.
- Backups write format v3 and still restore v1 and v2; backup recipes reuse `RecipeCreate`,
  so a bad link in a file is an `invalid_document` error, not a crash.
- The leftovers rule is pure (`leftovers.ts`) and goes through the existing optimistic,
  per-week serialized `assignSpecial`, in one request with the note.

## Accepted as-is
- Quantities stay in the free-text ingredients, so the shopping list groups them as
  before (ADR-0020).
- The leftovers link is only the note text: renaming the recipe later doesn't update it.
- The leftovers action is hidden, not disabled, when the next slot is taken or it is
  Sunday dinner; it never crosses into the next week.
- `steps` cannot be `null` in a PATCH; clients send `[]` to clear it (README).
- The seed recipes get no servings or steps; the seed only adds missing recipes anyway.
