# Review 0009 — v0.16.0 installable app and offline reading (planning/review model: Opus)

Scope: the v0.16.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (283 pytest, 374 vitest, ruff, mypy --strict, tsc for
the app and the worker, ESLint).

## Code review
- Routing is a pure, tested function. Non-GET and cross-origin requests, `/api/auth/*`,
  `/api/backup*` and `/api/health` are never touched; other API reads are network-first.
  Only a 200 same-origin response is cached.
- Privacy: a 401 from the API deletes the `cociboard-api` cache inside the worker, and
  logout (or an expired session) deletes it from the page.
- Updates: the worker never skips waiting on its own; the page posts `SKIP_WAITING` after
  the user taps Reload and reloads once on `controllerchange`. Old shell caches are removed
  on activate. `sw.js`, `/` and the manifest are served `no-cache`, hashed assets
  `immutable`.
- Queries use `networkMode: "offlineFirst"`, so a fresh offline load reaches the worker's
  cache; mutations keep `"online"`, pause offline and resume in order (per-week scopes are
  unchanged).

## Verified manually
Production build served by the backend on 8765 (`COCIBOARD_STATIC_DIR=frontend/dist`):
- The worker registers and controls the page; the shell cache holds the app files and, from
  the second load on, `cociboard-api` holds the weeks and recipes.
- With the backend stopped, reloading `/?week=2026-11-16` at 1440px shows the planner and
  the recipe list from the cache, and the offline banner.
- Offline (`offline` event), placing a recipe in Monday lunch updates the grid at once and
  the banner says "1 cambio pendiente de guardar". After restarting the backend and the
  `online` event, "Conexión recuperada" is announced and the server log shows
  `PUT /api/weeks/2026-11-16/days/0/lunch 200`; the week on the server has the meal.
- 375px: the offline banner sits under the header with no horizontal scroll and doesn't
  touch the tab bar.
- Update: after changing the served `sw.js`, `registration.update()` installs a waiting
  worker, the "Hay una versión nueva disponible. Recargar" bar appears at the top, and
  Recargar reloads under the new worker with the bar gone.
- Icons look right (plate, fork and knife on the primary colour); PNG sizes match the
  manifest.
- Podman image: `/`, `/sw.js` and the manifest are 200 with `no-cache`, the manifest is
  `application/manifest+json`, icons are PNG, hashed JS is `immutable`.

Note: the in-app browser only fetches worker scripts from servers it started itself; a
backend started from the shell fails `register()` with "unknown error when fetching the
script" without any request reaching the server. That is a limit of the test browser,
not of the app.

## Findings
None needing a code change.

## Accepted as-is
- The first visit doesn't fill the API cache: its requests run before the worker controls
  the page. From the next load on, offline reading works.
- `navigator.onLine` only knows about the network interface. If the phone is online but
  the server is unreachable, there is no offline banner. Reads still fall back to the
  cache, but edits fail and roll back as before.
- Offline edits live only in the open page. A `beforeunload` warning protects them; closing
  the app anyway loses them (ADR-0019).
- The service worker needs a secure context: on plain `http://nas:8000` the app works,
  installs to the home screen, but has no offline mode. The README says so.
- `theme-color` changed from #c2562d to #b9461f, the real `--color-primary`, to match the
  manifest.
- `PUBLIC_FILES` in `sw/shared.ts` must list any new file added to `public/`.
