# Review 0014 — v0.20.0 pantry staples (planning/review model: Opus)

Scope: the v0.20.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (389 pytest, 441 vitest, ruff, mypy --strict, tsc,
ESLint, version check).

## Code review
- `PantryItem` is global (not per week) with a unique folded `key`; migration 0006 creates
  the table and the unique index. Adding an existing key returns it (200), never 409.
- Suggestions are a pure function: ingredients of active recipes counted once per recipe,
  at least 3 recipes, top 8, keys already in the pantry left out.
- Shopping items get `in_pantry` by exact key; extras never do. Backups are format v4 with
  the pantry; v1–v3 still restore with an empty pantry.
- Pantry changes are optimistic on the pantry query and on every cached shopping list, in
  one serialized `pantry` scope, rolled back with a toast on error and paused offline like
  the other mutations.
- The browser's key folding (`toLowerCase` + NFKD) can differ from Python's `casefold` for
  rare letters such as "ß". It only drives the instant update; the server's key is what is
  stored and returned, so the list settles correctly after the request.

## Findings
None needing a code change.

## Accepted as-is
- Matching is exact on the folded name: "Aceite de oliva" doesn't cover "Aceite de oliva
  virgen extra" (explained in the panel, README and ADR-0023).
- The pantry keeps the spelling typed first ("aceite de OLIVA"); the list shows the
  recipe's spelling.
- Pantry rows in the shopping list have no checkbox; a tick stored earlier for that week is
  kept but not editable there.
