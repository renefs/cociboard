# Review 0016 — v0.22.0 print and share (planning/review model: Opus)

Scope: the v0.22.0 working tree written by the development subagent (Sonnet), before the
commit. Gates: `make check` passes (560 pytest, 542 vitest, ruff, mypy --strict, tsc,
ESLint, version check). Frontend only: no API, schema or migration change.

## Code review
- Printing renders `PrintWeek` / `PrintShopping` through a portal into `body > .print-root`
  and calls `window.print()` one frame later. The content is removed on `afterprint`. A
  print stylesheet shows only that root, in black on white, A4 portrait.
- `shareText.ts`, `ical.ts` and `shareActions.ts` are pure or thin and tested.
- `shareOrCopy` tries the share sheet first, then the clipboard, then a dialog showing the
  text for manual copy. The dialog matters on plain-http LAN access, where no clipboard API
  exists.
- The `.ics` file:
  - escapes TEXT values;
  - folds lines at 75 UTF-8 octets without splitting a character;
  - uses stable `<date>-<slot>@cociboard` UIDs, so a re-import updates the events;
  - uses floating local times: 14:00 for lunch and 21:00 for dinner.
- The shopping list's existing Copy/Share now goes through `shareOrCopy`. `shoppingAsText`
  reuses the existing `shoppingListText`, which keeps the "check at home" pantry line.

## Findings
- Fixed: the print stylesheet hid the whole app in every print. A plain Ctrl+P, with no
  print job, would have given a blank page. The rules now apply only while the print root
  has content (`body:has(> .print-root:not(:empty))`). Without a job the app prints as
  before (checked by switching the print rules on with an empty root).
- Fixed: the Spanish title read "Menú de 16 nov – 22 de noviembre de 2026", which is
  awkward and mixes two date formats. It is now "Menú semanal: 16 nov – 22 nov 2026"
  ("Weekly menu: …"), using the compact range from the planner header.

## Accepted as-is
- The shopping list heading, on screen and in print, still uses the existing long range
  ("16 nov – 22 de noviembre de 2026"); that predates this milestone.
- The `.ics` times are fixed at 14:00 and 21:00; household preferences (improvement 6)
  could make them configurable.
- If Safari on iOS doesn't fire `afterprint`, the printout stays mounted but hidden on
  screen until the next print replaces it.
- Not verified: a real print preview on paper, and sharing the `.ics` file to the calendar
  app on iOS or Android.
